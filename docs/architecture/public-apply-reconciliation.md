# Read-only public apply reconciliation

The default-off `experimental-linux-public-apply` SDK exposes
`reconcile_public_apply` for one explicitly selected archived job. It holds
the existing shared native lease throughout the inspection. The stage-only
and legacy readers retain their dialects. This entry has no writer, live
grant, retry, cleanup action or CLI selector.

The caller independently selects the owner profile and verifier, admitted
canonical public Plan and leaf, private Plan digest, raw job component,
held destination root and historical qualification. The checked SDK dialect
requires the original finite Plan expiry. An expired Plan can be inspected
using independently retained historical approval inputs. Current approval
and reader build identity do not authenticate the archive. Qualification
claims inside the candidate job cannot select trust.

The reader verifies the signed public owner and actual job/root association,
canonical private Plan, approved content and policy, original time bounds and
every accepted journal predecessor. It distinguishes the last complete
semantic boundary from a torn tail. After the metadata record, only the
mandatory public-v2 intent and consecutive successful observation, durability
and receipt commitment are admitted. Other dialects and unsupported cuts
refuse without changing artifacts.

The first segment retains its 64 MiB bound. Bytes after the actual kind-4
seal have a separate 4096-byte bound, including incomplete, torn and
receipt-missing histories. Physical EOF is checked independently of bounded
reader exhaustion. The owner, Plan, journal and receipt objects opened for this inspection
and their enclosing directory pins or observed absence remain held through
final name, identity, stamp and EOF checks. Later segment borrows retain
the same cursor. Terminal verification uses positioned rereads.

Current names are separate observations. A different occupant or unqualified
recorded identity match receives metadata inspection only. Accepted kind 7
must first bind the selected historical qualification. An actual native
eligibility holder must then match the held source and destination roots,
boot, mount namespace, unique mount and device. Without that recorded and
current association, the result supplies no data aperture or qualified
continuity. Device and inode numbers alone do not prove an original object.

For an eligible candidate, an `O_PATH` pin establishes regular-file identity,
same mount, current ownership, one link and required stat facts. A same-inode
read-only `O_NOATIME` reopen has no ordinary-read fallback. Empty visible
xattrs are checked on that descriptor before content reads. Required atime,
metadata and stable ctime are checked before and after digest and exact EOF
measurement. These observations rely on the selected cooperative custody
profile and do not establish an inode generation after arbitrary replacement.

A recorded kind 18 is a historical frame until the actual canonical receipt
validates. The reader captures the literal suffix from the same held segment,
validates it with the actual receipt, and requires the returned terminal head
to equal the first scan's accepted kind-18 head. Receipt identity means the
same current artifact remains pinned during inspection. V2 does not encode
the original receipt inode.

`CurrentMatchesCommittedEvidence` requires clean terminal closure, matched
qualified scope, the actual stage-directory identity matching kind 9, absence of the former
private name, the selected target's verified stream and metadata, a matching
receipt and all final custody checks. Other results keep historical claims and current
metadata distinct, including clean pre-intent and unavailable-artifact results.
Incomplete post-intent evidence requires reconciliation. Returned
values convey no native capability, permission or suggested action.

Source controls cover every authored nonempty complete cut, torn boundaries and suffix limits,
wrong qualification and trailing bytes, metadata-only pre-intent observations,
same-byte parent rebinding and the exact `O_NOATIME` aperture. The existing
owned ext4 selector also calls the SDK on an archived pre-intent job. These
controls and the source integration await execution at the integrated revision.
Positive operational publication/reconciliation and process-crash or power-loss
qualification remain separate gates.
