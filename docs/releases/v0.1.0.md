# ExaCopy v0.1.0 testing prerelease

This GitHub prerelease is for hands-on testing before publication to crates.io.
The archives contain an executable and the Apache-2.0 license. Check the
download against `SHA256SUMS.txt`, extract it, and run `exacopy --help`
(`exacopy.exe --help` on Windows). These testing archives are unsigned and
are intended for manual extraction. Production publisher trust, platform
signing and notarization remain pending.

## Downloads

| Archive | Current testing scope |
| --- | --- |
| `exacopy-cli-x86_64-unknown-linux-gnu.tar.gz` | Linux x64: local comparison, manifests, preserve-mode copy and recovery, and single-subject sync preview. Built on Ubuntu 22.04 with a glibc 2.35 ABI ceiling. |
| `exacopy-cli-aarch64-apple-darwin.tar.gz` | Apple Silicon: managed APFS comparison. The binary targets macOS 14.0; the release fixture runs on macOS 15. |
| `exacopy-cli-x86_64-pc-windows-msvc.zip` | Windows x64: CLI surface and unsupported-operation reporting. The separately tested NTFS staging capabilities are not enabled as general copy commands in this build. |
| `exacopy-cli-v0.1.0-x86_64-unknown-linux-gnu-experimental-ssh-wireguard.tar.gz` | Separate Linux x64 build with experimental SSH/SFTP and embedded WireGuard commands enabled. |

On macOS/Linux, `shasum -a 256 ARCHIVE` prints the archive digest. On
Windows, use `Get-FileHash ARCHIVE -Algorithm SHA256`. Compare the result
with the matching entry in the checksum index.

## Experimental remote testing

The experimental Linux build exposes `get` and `recover remote-resume`.
It requires the explicit credential, host-key, route, destination
qualification and profile setup in the
[CLI guide](https://github.com/replicraft/ExaCopy/blob/v0.1.0/apps/exacopy-cli/README.md#experimental-ssh-download-on-linux).
Current recovery can start a new authenticated read from byte zero while
preserving the previous private stage. The hosted direct-SSH fixture has
exercised timeout redial, grant expiry, cancellation, the original retry
budget and wrong-host-key refusal. Data-only transfers explicitly report
metadata omissions.

Efficient retained-prefix reuse, end-to-end witnessed closeout and
independent kernel WireGuard commissioning remain qualification work.
The witnessed components and ignored fixtures in the source do not enable
those guarantees in the public command. Deployment qualification,
ordinary-user Windows copy/recovery, protected replacement, persistent sync
baselines and power-loss durability also remain open. Dependency review
is incomplete, so this is not a production-qualified release.

## Source and feedback

The release is built from the immutable `v0.1.0` tag using Rust 1.100.0 and
the root lockfile. Native build metadata and software bills of materials
accompany the downloads. Crates.io publication will follow user testing.

When reporting a result, include the archive name, operating system,
command, exit status and whether the operation was interrupted. Existing
source and destination preservation and explicit refusal behavior remain
the expected contract during testing.
