# First witnessed SSH resume

This default-off Linux integration continues one clean original V1 capture.
It reuses its held private stage after comparing the retained prefix with the
current remote file through the same authenticated SFTP handle used for the tail.
It rereads the remote prefix and does not reduce prefix network traffic.

The first hosted Linux lane at `b82d0f3` passed 183 controls, including all eleven
required selection, authority and report cases. That cohort also exposed strict
lint and report-inventory failures, retained with their focused follow-ups.
The integrated repair must pass its own CI before promotion. Native operation-2
qualification for this CLI composition remains pending; lower-level tests and
synthetic report projections do not qualify it.

## Explicit selection

Build with `experimental-verified-prefix-resume`; embedded WireGuard additionally
requires `experimental-ssh-wireguard`. The feature does not change the ordinary
byte-zero command or either published registry feature projection.

Only `remote-resume JOB` accepts this mutually required group:

- `--strategy verified-prefix-with-witness-v1`
- `--allow-witness-retention`
- `--continuation-qualification FILE`
- `--continuation-trust FILE`

The ordinary profile, SSH profile, destination qualification, qualification trust,
and `--metadata sftp-data-only-v1` remain required. The new artifact and trust
paths must differ from each other and from both ordinary qualification paths.
All use the existing bounded protected-file admission rules.

The additional trust JSON uses schema
`exacopy-remote-witness-qualification-trust-v1`, with `attestor`, `attestor_key`,
`build`, `route`, `campaign_scope` and `campaign_evidence`. Hex fields are bounded
by the existing exact-width decoder. Route is `direct-pinned-tcp-v1` or
`embedded-wireguard-tcp-v1`. The independently signed artifact must bind operation
`VerifiedRetainedAppendWithWitnessV1` and coverage
`RetainedAppendWithWitnessProcessCrashV1`, including all required campaign cases.
Its signer must differ from the job owner. Current executable, route, destination,
kernel, boot and mount facts must match. Qualification proves the declared
operating envelope; it does not itself authorize a job or supply user consent.

## Authority and held evidence

The foreground owner explicitly selects the retained job and its unchanged
authenticated scope under the current protected SSH and local profiles. That
invocation supplies fresh finite authorization and explicit retention consent.
The grant binding includes a fresh kernel nonce. An original V1 capture records
no earlier runtime grant or expiry; this first witnessed invocation does not
claim to recover such a grant. It cannot change the signed source, endpoint,
destination or plan, and it cannot revive a previous witnessed invocation.

Local donor bounds refuse an oversized uncheckpointed extent or a stage at the
signed maximum before dialing. Equality to an earlier source length remains
admissible below that maximum because the current source can have grown.

The shared lease and exact file pins survive authentication. Before credentials
or route effects, admission rechecks the selected donor; the exclusive handoff
then rechecks the same job, owner, full journal boundary, stage directory, stage
and target. A substituted file or advanced history requires reconciliation.
The continuation retains the current grant and same held SFTP source across
prefix verification and tail consumption. A whole-file hash supplied separately
would not replace comparison of the skipped remote prefix.

Admission is limited to a clean original capture with a checkpoint, a positive
tail, no prior witnessed link, no recorded retirement and no finalization intent.
Current verified operation-1 evidence fills the initial and fresh V1 archive
roles only within that restricted history. Later witnessed restart, grant
rebinding, automatic witnessed retries and implicit byte-zero fallback are not
implemented by this mode.

## Publication and output

The existing kind-40/41/42 witness protocol drives the checked native operations.
This mode uses the existing wire record types. Success requires actual native publication
evidence and a committed kind-18 receipt after witnessed closeout. Native
publication without that receipt, uncertain effects, and unconfirmed conflict
records require reconciliation. A confirmed conflict remains a conflict.

Successful JSON uses `exacopy.cli.witnessed_remote_download` version `1.1` and
exit 11 (`published_with_omissions`). It reports the receipt digest, qualification
digest, length, retained witness link count, committed sequence and head digest,
and canonical receipt length. The receipt adds `archive_selection` for later
read-only inspection. It omits the ordinary
full-stream `blake3` field. Ordinary byte-zero success remains
`exacopy.cli.remote_download` version `1.0`, including that field. Common failures
retain the ordinary failure schema and their known publication state.

Retention consent permits a private hard link to the published file. Preserve
the job and witness as evidence. Data-only metadata omissions remain explicit.
Ctrl-C revokes the grant, and expiry blocks further effects; incomplete effects may require
reconciliation rather than a clean cancellation report.

## Read-only terminal inspection

Capture the complete successful `--format json` output from a trusted witnessed
invocation and retain it separately from the job as a protected JSON file.
The selection comes from that trusted capture. File protection controls its
local custody. Version `1.0` success lacks archive selection and is refused.
The inspector does not reconstruct missing selectors.

On the same feature-enabled Linux build, select the job path and original
qualification inputs explicitly. The archived display and raw path fields
are diagnostic. Job lookup uses the parent and basename selected by `JOB`.

```text
exacopy recover remote-inspect-witness JOB --selection-report FILE \
  --destination-qualification FILE --qualification-trust FILE \
  --continuation-qualification FILE --continuation-trust FILE --format json
```

The inspector accepts a clean submitted kind-18 terminal receipt from the
first witnessed continuation. It checks the exact held terminal boundary,
public file contents and length, retained witness and final receipt. JSON
output uses
`exacopy.cli.witnessed_remote_inspection` version `1.0`. It reports the observed
association at inspection time. The executable must match the original
measured image, and the held destination facts must match the selected
qualification, including current boot and mount facts. An upgrade, reboot
or remount can make the original archive ineligible.

The command verifies the archived owner with its public key and holds a
shared recovery lease. It requires no private key or SSH session and grants
no live or mutation authority.

## Verification boundary

confirmed publication without its committed receipt cannot become CLI success.
Parser and report regressions check selection and output compatibility. The
dedicated hosted lane includes those cases and existing signed-kind-40 controls.
The lane also checks inspection argument selection, archive decoding, terminal
selection and report projection. The new inspection controls are inventoried
and source reviewed; their integrated hosted execution is pending. These
controls do not establish native custody, live
remote-source comparison, process-crash or power-loss qualification.
Those require their own evidence before promotion.
